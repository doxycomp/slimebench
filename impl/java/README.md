# Java — tier A without a keyword

Between Java 1.2 and Java 17, `float` arithmetic on x86 was allowed to be
evaluated in x87 extended range unless a method or class was marked `strictfp`.
JEP 306 removed that permission: since Java 17 every floating-point operation
is strict IEEE 754, and `strictfp` is a no-op kept for source compatibility.
This port is therefore tier A by default on 17 and later, and would have needed
`strictfp` on 8 through 16.

The other half is contraction. The JLS has always required each operator to
round its own result — there is no equivalent of C's `-ffp-contract`, and a JIT
may not fuse `a + b * c` into an FMA. `Math.fma` exists precisely because
fusing has to be asked for. So the stencil here is written plainly, without the
`float32(...)` conversions the Go port needs for the same guarantee.

Java also has no unsigned 32-bit integer, and does not need one: `int`
arithmetic wraps modulo 2^32, which is exactly what SPEC-1 §3.1 requires. The
only places signedness shows is the shift — `>>>` rather than `>>` — and the
hash formatting.

Two results worth knowing before reading: Java is the fastest garbage-collected
runtime in class S **and** the slowest of the compiled languages to scale in
class P, and the second is not a barrier problem. Its work per thread stops
halving after eight and goes back up at thirty-two, which the phase
instrumentation shows and does not explain.

## Reading order

`src/Sim.java` — the class comment is the exactness argument above. Then
`src/Parallel.java` for class P and `src/Simd.java` for the Vector API, which
names no width at all (`SPECIES_PREFERRED`) and still takes the full 512 bits.

## Building

```bash
bash impl/java/build.sh default
```

The `c2` profile disables tiered compilation, which makes the JVM reach steady
state *sooner* rather than later — see [docs/RESULTS.md](../../docs/RESULTS.md)
§6, which also has the warm-up ramp.
