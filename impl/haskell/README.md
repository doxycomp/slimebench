# Haskell — two styles, measured against each other

This directory contains the same simulation twice, and that is the point.

**`src/Sim.hs`** is the low-level port: `IOUArray Int Float` in `IO`, strict
and unboxed throughout, hand-written tail recursion, explicit index
arithmetic. A Haskell programmer reading it described it as "what happens if
you take the C and re-create it line by line", which is accurate — nobody
would write it that way if they were not matching a reference statement for
statement.

**`src/SimVector.hs`** is what the advice usually is: pure functions over
immutable `U.Vector`, no `IO` below `runTicks`, the diffusion pass as one
`U.generate`, the deposit scatter as `U.accumulate`, the agent pass as
`U.unfoldrExactN`. Say what each output is and let GHC fuse.

The benchmark reports both. The question is not which style is nicer — it is
what the choice costs, in a language where the received wisdom is that it
costs little.

Two things matter more here than in any other port:

- **Strictness.** Without the bang patterns and `UNPACK`, the accumulator in
  the diffusion kernel builds a nine-deep thunk chain per cell and the grid
  becomes a graph of suspended additions. That is the difference between "a
  few times slower than C" and "unusable".
- **`unsafeRead` / `unsafeWrite` / `unsafeAt`.** Every index has already been
  masked with `width-1` or reduced mod NDIR, so the bounds check can never
  fire, but GHC cannot prove it. The `o2-llvm-safetrig` profile builds the
  same source with the ordinary `(!)` lookup instead, so the comparison can be
  re-run rather than remembered.

## Reading order

`src/Sim.hs` is 700 lines and the interesting parts are marked with section
comments: the PRNG, `trigAt` with the `SB_SAFE_TRIG` switch, `agentSort` for
the spatial ordering, the tick, and the checksums at the end.

`hashAgents` is worth a moment: the last real bug in this port was there, a
recursion that walked the slot index instead of the agent index. The grid hash
stayed correct and only the agent hash diverged, which is exactly what the
two-checksum split in SPEC-1 §6.3 exists to localise.

Then `src/SimVector.hs` for the contrast, and `src/Parallel.hs` for class P —
`forkOn` green threads pinned one per capability over shared `IOUArray`s, with
an `MVar` barrier. The header there argues why not STM: `retry` is the
prettier Haskell, but every waiter re-validates its transaction on each wakeup.

`src/MainRaylib.hs` binds raylib with plain `foreign import ccall` rather than
through `h-raylib`, because `h-raylib` vendors and builds its own copy of the
library — using it would compare a Haskell program against a *different build*
of raylib than every other target in class R.

`src/DirTable.hs` and `src/Font.hs` are generated. Do not read them to form a
judgement; CI regenerates both and fails if the committed output differs.

## Building

```bash
bash impl/haskell/build.sh o2-llvm
```

`ghc` is invoked directly rather than through cabal: the low-level target
needs nothing outside `base`, `array` and `bytestring`, which keeps the
optimisation profile a command-line flag instead of a package-description
edit. The `-vector` profiles need the `vector` package and the `-sdl2` profile
needs `sdl2`; `build.sh` compiles a probe import and says so if they are
missing.

The style comparison in numbers is [docs/RESULTS.md](../../docs/RESULTS.md)
§4; the language table is §2 and the barriers are §5.
