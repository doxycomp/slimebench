# OCaml — the mirror image of the Lean port

These two ports exist as a pair, and each is what the other is not.

Lean has a native `Float32` — IEEE binary32, verified — but `Array Float32`
stores every element as a heap object, so the data is boxed and the arithmetic
is exact. OCaml 4.14 is the other way round on both counts. A `float array` is
stored flat and unboxed, which is the representation Lean cannot express; but
there is no float32 type at all, every `float` is binary64, and the only route
to conformance tier A is to round every intermediate by hand.

How that rounding is done turned out to matter more than anything else in this
port. Three ways to reach tier A were measured — no rounding at all (which is
tier B and a different computation), an `Int32` bit round-trip, and a C stub —
and they span a factor of five. `f32_stub.c` is a single SSE instruction
wrapped in the cheapest call OCaml can make, `[@@unboxed] [@@noalloc]`, doing
the whole conversion in one call instead of two: **twice as fast for one
line**, bit-identical, full conformance set. It also reversed the ordering
against Lean, which an earlier version of the results had the other way round.
The three rows are in [docs/RESULTS.md](../../docs/RESULTS.md) §2.

The microbenchmark that measures it has to put the rounding *on* a dependency
chain: measured beside it, the round-trip looks almost free, because what costs
is latency the chain cannot hide.

`sim.ml` — the header is the comparison above. `f32_stub.c` is twenty-four
lines and worth reading in full. The `cstub` profile rewrites one line of
`sim.ml` at build time rather than keeping two copies of the file.
