# Lean 4 — a proof assistant asked to run a loop

The other ports answer "how fast is X". This one answers a different question:
what does a proof assistant's compiler do with a workload that is nothing but
mutable arrays and float arithmetic? It is the only target here whose language
was not designed with this kind of loop in mind, and the interesting part is
that it reaches conformance tier A at all.

It also does something no other port can, which is the reason the directory has
a `Proofs/` subdirectory rather than only a `Slimebench/` one.

## Two claims, machine-checked

`Proofs/` verifies two things SPEC-1 asserts, that every implementation depends
on, and that nothing else here checks except by running it and comparing a
hash:

- **`Proofs/Binned.lean`** — the spatially binned parallel deposit applies each
  cell's deposits in exactly the serial order, at any thread count and any
  partition. That is the property the whole of class P rests on, and it is why
  `binned` can be bit-identical to a single-threaded run.
- **`Proofs/Index.lean`** — the bit-masked torus index equals the modulo index,
  stays inside the grid, and is injective.

Neither proof mentions floating point, and that is deliberate rather than a
limitation — the header of `Proofs/Binned.lean` says why.

## What Lean pays, and where

`Array Float32` stores every element as a heap object. Once an array is shared
with a task, Lean marks it multi-threaded and reference-counts it atomically,
so nine reads per cell become nine atomic read-modify-writes. That is why
`Bench/Tasks.lean` exists: the class-P question here is not about barriers at
all, it is about *ownership*, and the program measures the three shapes
ownership allows. The best of them reaches a fraction of what the other ports
get from the same number of cores, and the port therefore ships class S only —
putting a 1.2x row next to languages that parallelise the whole tick would
compare two different things.

Read `impl/ocaml/README.md` next: the two ports are exact opposites on both
boxing and float32, which is why they exist as a pair.

why those two claims, `Bench/Tasks.lean` for the ownership experiment.
