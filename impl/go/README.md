# Go — where the rounding is written out

Go's specification permits an implementation to fuse floating-point operations
"into a single fused operation, possibly across statements", which would turn
`acc + 4.0*g` into one FMA with one rounding instead of two. That is the same
hazard C needs `-ffp-contract=off` for, except Go puts the fix in the language
rather than in a flag: an explicit conversion to a floating-point type rounds
to that type, and the rounding may not be discarded.

So the stencil says `acc + float32(4.0*g)`. The conversion looks redundant —
both operands are already `float32` — and it is the thing that makes this
target conformance tier A on every architecture rather than only on the one
where the compiler happened not to fuse.

What is deliberately not done: no `unsafe`, no manual bounds-check elision. Go
has no equivalent of Rust's `unchecked` feature that stays inside the language,
and adding an unsafe variant would measure how much unsafe one is willing to
write rather than what Go costs.

**Go wins class P**, which was not expected and is the reason the barrier
instrumentation in §5 exists. It is not the compute: the work per thread is
indistinguishable from C's. It is the barrier, and the gap concentrates in the
one phase where thirty-one workers wait for one.

## Building

```bash
bash impl/go/build.sh nobounds
```

`bash build.sh`, not `./build.sh`: the script is mode 644 in git, and a
container copies that faithfully where WSL on a Windows filesystem reports
everything as executable.
