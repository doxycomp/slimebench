# TypeScript — f32 arithmetic in a language that has none

JavaScript has no `float32` arithmetic. `a + b` on two values read out of a
`Float32Array` is computed in f64, and SPEC-1 §1.2 requires every single
operation to round to f32.

`Math.fround(f64_op(a, b))` is provably identical to the f32 operation for
`+`, `-`, `*` and `/`: double rounding is harmless when the intermediate format
has at least 2p + 2 bits, and 53 >= 2*24 + 2. So this port is bit-exact with
the C reference rather than merely close to it, and `Math.fround` appears on
every arithmetic operation in `src/sim.ts` for that reason.

Two things about this target are worth knowing:

- **It scales as well as Go does** in class P, from a starting point three
  times behind C in class S. Class P uses a `SharedArrayBuffer` with real
  worker threads, not an event-loop trick.
- **`src/sim.ts` is shared unchanged** between the Node benchmark and the
  browser frontend. No DOM and no Node API appear in it, which is what makes
  the browser page a demonstration of the same simulation rather than a second
  implementation of it.

## Reading order

`src/sim.ts` first. Then `src/shared.ts` for the SharedArrayBuffer layout and
the barrier, and `src/parallel.ts` for the tick that the main thread and every
worker run identically.

## Building

```bash
node --experimental-strip-types impl/ts/src/main-node.ts --preset small --ticks 600
```

There is no compile step for the headless target: Node strips the types. The
browser bundle is built separately with `npm run build:web`, which emits
`impl/web/app.js`; see [`impl/web`](../web/).
