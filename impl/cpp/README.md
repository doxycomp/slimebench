# C++ — the same algorithm, written the way C++ is written

Not a transliteration of the C reference. `std::vector`, `std::array`,
`std::bit_cast`, RAII, namespaces — the abstractions stay in on purpose,
because the question this port answers is whether they cost anything. If g++
and gcc produce different performance from structurally identical algorithms,
that difference is the finding.

Three things are deliberately *not* idiomatic, and each has a reason that is
not about taste:

- **No `std::mt19937`.** SPEC-1 §3.1 mandates xoshiro128++, because
  cross-language equality needs one generator, not one per standard library.
- **No `std::sinf`.** SPEC-1 §4 mandates the generated direction table; libm
  results are not bit-identical between platforms.
- **Struct-of-arrays for the agents**, not an array of structs, because the
  SIMD and GPU tiers need that layout and a different one here would make the
  class V comparison a comparison of memory layouts.

The C++ port is the only other one besides C that carries every class, which
makes it the control whenever a C result might be an artefact of C rather than
of the machine.

## Reading order

`sim.hpp` — types, tick, and the three non-idiomatic decisions above stated in
the header. Then `agent.hpp` for the per-agent rule, `parallel.hpp` for the
threaded tick, and `simd.hpp` for class V.

`simd.cpp` is worth a look for how the width comparison is kept honest: `Vec`
and the one-line load/add/mul helpers are bound to `__m512` or `__m256` at
compile time, so AVX2 and AVX-512 are the same source text at two widths
rather than two hand-written kernels.

## Building

```bash
make -C impl/cpp CXX=g++ PROFILE=o3-native headless
```

`sdl2` and `raylib` build the windowed frontends. The compiler comparison —
including the one where `-Ofast` costs clang half its speed and gcc nothing —
is [docs/RESULTS.md](../../docs/RESULTS.md) §3.
