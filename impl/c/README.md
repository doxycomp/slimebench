# C — the reference implementation

This is the normative port. Every other language is verified against the
checksums this one produces, so the rule for this directory is different from
all the others: **keep it boring and literal.** Any deviation from
[`spec/SPEC.md`](../../spec/SPEC.md), however clever, is a bug — and it is a
bug in fourteen languages at once, because they all agree with this one by
construction.

It is also the widest implementation in the project. C is the only directory
that carries every benchmark class: one thread, threads, vectorised, ordered,
and two windowed frontends. That is deliberate — when a class needs a control,
the control is here, so the effect being measured is not confounded with a
change of language.

Three things in this directory are experiments rather than infrastructure:

- **`sb_simd_agents.c`** vectorises the *agent* pass, which nothing did until
  recently. The header of `sb_simd.h` had asserted — without measuring — that
  it could not usefully be done, because three sensor reads per agent are a
  gather with data-dependent addresses. That was wrong, and the file exists
  because it was measured.
- **The spatial ordering** in `sb_core.c` (`--agent-tile N`) counting-sorts the
  agents into 8×8 tiles of the grid every N ticks, so the sixteen lanes of a
  gather land in a few cache lines rather than sixteen unrelated ones. On a
  grid that fits in cache it is a net loss, which the tables report as plainly
  as the win.
- **`sb_verify.h`** turns the whole thing into a hardware check. Because
  SPEC-1 fixes the result, a chain of checksums recorded once on a healthy
  machine is a reference for every machine, and a mismatch is not a slow
  computer but a wrong one.

## Reading order

`sb_core.h` first — it is the data layout and the tick, and it is short.
Then `sb_agent.h` for the per-agent rule (shared verbatim by the serial and
threaded paths, which is what stops them drifting apart), and `sb_core.c` for
the diffusion stencil, where the normative summation order lives.

After that, by interest: `sb_parallel.c` for the six-barrier tick and the two
reduction strategies, `sb_simd.h` for the vectorised stencil and its tier-A
argument, `sb_simd_agents.c` for the harder half of the same problem.

The place a reader is most likely to have an opinion is the dead-end handling
in `sb_simd_agents.c`: lanes that need a random draw are peeled off and done
scalar, because a lane that drew speculatively would advance a PRNG stream
that must not advance.

## Building

```bash
make -C impl/c CC=gcc PROFILE=o3-native headless
```

`sdl2` and `raylib` build the windowed frontends; `ASM=1` links the
hand-written kernel from [`impl/asm`](../asm/). Measurements are in
[docs/RESULTS.md](../../docs/RESULTS.md) — this port appears in almost every
section.
